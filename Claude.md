# Sky Fighter - Codebase Guide for Claude Code

## Project Overview

**Sky Fighter** is a browser-based vertical shoot-'em-up game (Raiden-style) with the following core features:
- Player-controlled aircraft with weapon switching
- Enemy waves and stage bosses
- Power-ups and smart bombs
- Real-time canvas-based rendering
- Responsive design for desktop and mobile

**Tech Stack:**
- Pure HTML5/Canvas (no frameworks)
- Vanilla JavaScript (ES6+)
- Single-file architecture (index.html)

## Codebase Structure

The entire game is implemented in a single `index.html` file (~1500+ lines) with embedded CSS and JavaScript.

### Key Sections (in order):
1. **HTML Head**: Meta tags, viewport config, dark theme styling
2. **CSS**: Game styling, canvas layout, HUD, pause menu, game over screen
3. **JavaScript Game Engine**:
   - Game state and constants
   - Player entity and controls
   - Enemy types and spawning system
   - Weapon system and projectiles
   - Collision detection
   - Rendering pipeline
   - Input handling (keyboard, mouse, touch)
   - Main game loop

## Architectural Patterns

### Entity-Component Design
- Entities (player, enemies, projectiles, effects) are plain objects with properties
- Behavior is implemented through update/render functions
- Collision detection via bounding box calculations

### Canvas Rendering Pipeline
- Double-buffering handled by canvas API
- Render order: background → entities → effects → HUD
- Efficient redraw using requestAnimationFrame

### Game States
- `IDLE`: Before game starts
- `PLAYING`: Active gameplay
- `PAUSED`: Game paused
- `GAME_OVER`: Loss condition
- `BOSS_DEFEATED`: Victory condition

### Weapon System
- Multiple weapon types with different firing patterns
- Weapon switching via number keys or UI
- Fire rate and damage scaling

## Development Guidelines

### When Making Changes

1. **Test in Browser**: Always test changes by opening `index.html` in a browser to verify game functionality
2. **Incremental Changes**: Make small, focused changes to avoid breaking the game loop or collision detection
3. **Performance**: Canvas games are performance-sensitive; avoid expensive operations in the main loop
4. **Mobile Considerations**: Game supports touch input; test on mobile devices when modifying controls

### Code Organization

- Keep entity properties simple and flat (avoid deep nesting)
- Update functions should modify entity state directly
- Render functions should be pure (no side effects)
- Game constants are defined at the top for easy tweaking

### Common Tasks

**Adding a New Enemy Type:**
1. Define enemy template in the `ENEMY_TYPES` object
2. Add spawn logic in `spawnEnemyWave()`
3. Implement movement pattern in enemy `update()` logic
4. Test collision detection and despawning

**Adding a Weapon:**
1. Define in weapon system
2. Add weapon switch handling
3. Implement firing pattern in projectile update
4. Tune damage and fire rate

**UI Changes:**
- HUD elements are rendered in the render pipeline
- Pause menu and game over screen are overlays
- Use CSS classes for styling consistency

## Testing & Validation

- Open game in browser to test all changes
- Verify smooth gameplay at 60 FPS
- Test on mobile devices if UI/controls modified
- Check for memory leaks in long play sessions
