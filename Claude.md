## Development Guidelines

### Git Workflow

1. **Branch:** Always develop on `claude/inspiring-planck-0k78qr`
2. **Commits:** Use clear, descriptive commit messages
3. **Attribution:** Include the session attribution footer in commit messages
4. **Push:** Use `git push -u origin claude/inspiring-planck-0k78qr`

### Code Standards

- Keep code simple and maintainable
- Avoid over-engineering or premature abstractions
- Write meaningful comments only when the "why" is non-obvious
- Follow the principle of "three similar lines before abstracting"

### Testing & Validation

- Run tests before committing changes
- Validate changes work as expected before reporting completion
- For UI changes, test in a browser to ensure functionality

### Commits & Pull Requests

- Create commits with clear, concise messages describing what changed and why
- No pull requests should be created without explicit user request
- When creating PRs, respect the repository's PR template if one exists

## Important Notes

- Changes should be properly committed and pushed before the session ends
