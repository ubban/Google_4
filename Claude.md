# Claude Code Guidelines for Google_4

- `README.md` - Project metadata
- `index.html` - Main web page

## Development Branch

All feature development work should be done on the branch:
- **`claude/inspiring-planck-g1b8wf`**

Push all completed work to this branch using:
```bash

```

## Git Workflow

### Commits
- Write clear, descriptive commit messages
- Include the attribution footer in all commits:
  ```
  Co-Authored-By: Claude Haiku 4.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_01PWjgf5trqoKi6RombVTnUb
  ```

### Push Strategy
- Always use: `git push -u origin <branch-name>`
- On network failures, retry up to 4 times with exponential backoff (2s, 4s, 8s, 16s)

### Pull Requests
- Do NOT create pull requests unless explicitly requested
- When creating PRs, check for PR templates in:
  - `.github/pull_request_template.md`
  - `.github/PULL_REQUEST_TEMPLATE.md`
  - `PULL_REQUEST_TEMPLATE.md` (root)
  - `docs/PULL_REQUEST_TEMPLATE.md`

## Code Standards

### HTML/Web Assets
- Use semantic HTML5
- Keep index.html well-structured and accessible
- Test changes in a browser before completing work

### General Principles
- Prefer editing existing files to creating new ones
- Keep changes minimal and focused on the task at hand
- Write comments only when the WHY is non-obvious
- Delete unused code rather than commenting it out

## Testing and Verification

- For any UI or frontend changes, start the dev server and test in a browser
- Test both the golden path and edge cases
- Monitor for regressions in existing features
- Type checking and test suites verify correctness, not feature completeness

## Documentation

- Keep README.md updated with current project information
- Update Claude.md whenever project structure or workflows change
- Document any new development dependencies or setup instructions
