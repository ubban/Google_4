# Sky Fighter - Codebase Documentation

## Project Overview

**Sky Fighter** is a Raiden-style vertical shoot-em-up game built as a single-file HTML5 application. It features dynamic difficulty settings, weapon progression, procedurally styled stages with unique themes, and boss encounters with health bars.

- **Type**: Single-file HTML5 Canvas game
- **Technology**: Vanilla JavaScript, HTML5 Canvas, Web Audio API
- **No external dependencies** - all rendering and audio synthesis is custom-built
- **Responsive design** - supports desktop (mouse/keyboard) and mobile (touch) controls

## Architecture Overview

### Core Structure
The entire application is contained in a single `index.html` file with three main sections:

1. **HTML Structure** (lines 361-420)
   - Game canvas
   - HUD elements (score, health, weapons, bombs)
   - Boss health bar
   - Overlay screens (menu, game over)
   - Touch controls (for mobile)

2. **CSS Styling** (lines 10-359)
   - Game canvas styling and effects
   - HUD animations and layout
   - Overlay cards and transitions
   - Touch control buttons
   - Accessibility features (reduced motion support)

3. **JavaScript Game Engine** (lines 422+)
   - Game state management
   - Entity systems (player, enemies, bullets, bombs)
   - Physics and collision detection
   - Audio synthesis (WebAudio API)
   - Input handling (keyboard, mouse, touch)
   - Rendering and animations

## Key Game Components

### Game State Variables
- **Player**: Position, health, weapon level, bombs, score, multiplier
- **Entities**: Arrays of enemies, bullets, explosions, pickups
- **Difficulty**: Spawn rates, enemy speed, enemy accuracy, lives, bombs
- **Stage**: Current stage number, theme, kills needed for progression
- **Boss**: Current boss, health, attack patterns

### Entity Types

#### Player
- Position and velocity
- Health/lives system (1-4 depending on difficulty)
- Weapon system (Vulcan, Spread, Aimed)
- Smart bomb capability (X or Shift key)
- Collision detection with enemies and projectiles

#### Enemies
Three types with different characteristics:
1. **Grunt** (red): Basic enemy, 1 HP, appears from stage 1
2. **Interceptor** (orange): Fast, nimble, 1 HP, weaves side-to-side
3. **Tank** (purple): Slow, heavily armored, 4 HP, appears from stage 2

#### Bosses
Six unique bosses cycle through stages:
- VANGUARD (stage 1)
- BEHEMOTH (stage 2)
- SPECTER (stage 3)
- DREADNOUGHT (stage 4)
- WRAITH (stage 5)
- TITAN (stage 6+)

Each boss has unique visuals and a health multiplier affecting difficulty.

#### Projectiles
- **Player bullets**: Generated by active weapon system, despawn when off-screen
- **Enemy fire**: Random projectiles from enemies based on difficulty
- **Explosions**: Visual and collision effects from bullets and bombs
- **Smart bombs**: Player-triggered area-of-effect damage

#### Power-ups
- **Weapon pickups**: Upgrade player's weapon (Vulcan → Spread → Aimed)
- **1-Up pickups**: Additional life (rare)

### Weapon System
Three progressive weapons:
1. **Vulcan** (Level 1-3): Straight-firing bullets from center
2. **Spread** (Level 1-3): Five bullets in a spread pattern
3. **Aimed** (Level 1-3): Bullets that track toward enemies

Weapons generate a multiplier bonus when active, encouraging use.

### Difficulty System
Three difficulty levels stored in localStorage:

| Setting | Easy | Normal | Hard |
|---------|------|--------|------|
| Spawn Rate | 75-40 | 58-26 | 40-18 |
| Enemy Speed | 1.0x | 1.4x | 1.9x |
| Enemy Accuracy | 45% | 70% | 95% |
| Lives | 4 | 3 | 3 |
| Bombs | 3 | 2 | 2 |
| Boss HP | 0.8x | 1.0x | 1.3x |

### Stage Progression
- Stages cycle through 6 themed environments
- Each stage requires 18 enemy kills to advance
- Bosses appear every 6 stages
- Themes include: Daylight Front, Sunset Corridor, Night Approach, Storm Front, Arctic Wastes, Volcanic Ridge

### Audio System
Custom WebAudio synthesis with no external audio files:
- **Beep generator**: Frequency-based tones with envelope, sweeps, and filters
- **Noise bursts**: White noise for impact sounds
- **Spatial audio**: Pan effects based on bullet/enemy position
- **Dynamic compression**: Master gain and dynamics compressor for audio management
- **Mute toggle**: Stored in localStorage

### Input Handling

#### Keyboard (Desktop)
- **Arrow Keys / WASD**: Move player
- **Mouse move**: Steer player (alternative)
- **Click / Space**: Fire weapon
- **X / Shift**: Smart bomb
- **P / Esc**: Pause game
- **Mute button (🔊)**: Toggle sound
- **Motion button (🎆/🚫)**: Toggle reduced motion effects

#### Touch (Mobile)
- **Left zone (55% width)**: Drag to move player
- **Right zone (45% width)**: FIRE and BOMB buttons
- **Joystick visual**: Optional (currently hidden, base structure present)

### Visual Effects

#### Screen Effects
- **Vignette**: Red pulsing edge effect when taking damage
- **Flash**: White flash on hit or bomb detonation
- **Screen shake**: Applied on bomb and significant hits
- **Combo popup**: Floating text for consecutive kills
- **Stage banner**: Text overlay when entering new stage

#### Animations
- **Heart beat**: Health indicator pulses when critical (< 2 lives)
- **Boss health bar**: Smooth transition on damage
- **Card entrance**: Smooth slide-in for overlay screens
- **Icon bob**: Floating animation on title
- **Reduced motion**: All animations disabled if prefers-reduced-motion is set

### Performance Management

#### Adaptive Quality
- Tracks frame times over ~2.5 seconds (45 frames)
- Automatically adjusts rendering quality:
  - Quality 0: Full details
  - Quality 1: Medium (some optimizations)
  - Quality 2: Low (aggressive optimizations)
- Targets 40-56 FPS range

## Game Mechanics

### Scoring System
- **Base score**: 10-35 points per enemy depending on type
- **Multiplier**: Increases with weapon selection (1.0x to 3.0x)
- **Combo**: Consecutive kills add up in real-time multiplier
- **Best score**: Stored in localStorage, displays on start screen

### Collision Detection
- **AABB (Axis-Aligned Bounding Box)**: Used for enemy-player and bullet collisions
- **Circular distance check**: Used for some proximity effects
- **Collision response**: Applies damage, knockback, and effects

### Enemy AI
- **Movement**: Linear downward movement with optional weaving (interceptors)
- **Shooting**: Random chance based on difficulty
- **Death**: Explosion effect, score award, potential pickup drops

### Boss Patterns
- **Fixed health pool**: Scales with boss type multiplier and difficulty
- **Projectile pattern**: Fires in specific patterns (currently simplistic, can be enhanced)
- **Movement**: Stays centered horizontally, moves up/down
- **Destruction**: Eliminates remaining enemy bullets, advances to next stage

### Game States
1. **Menu**: Difficulty selection and game start
2. **Playing**: Active gameplay
3. **Paused**: Game frozen, can resume
4. **Game Over**: Score display, option to restart

## Data Persistence

### localStorage Keys
- `skyfighter.bestScore`: Best score achieved
- `skyfighter.muted`: Audio mute state (0/1)
- `skyfighter.difficulty`: Last selected difficulty
- `skyfighter.reducedMotion`: Motion preference (0/1)

## Development Guidelines

### Code Organization
The JavaScript is organized into sections with clear comments:
1. DOM element references
2. Storage keys
3. Accessibility announcements
4. Performance tracking
5. Difficulty settings
6. Game constants (themes, enemies, bosses)
7. Audio system
8. Game state initialization
9. Input handling
10. Rendering and update loops
11. Game event handlers

### Common Patterns

#### Adding a New Enemy Type
1. Add entry to `ENEMY_TYPES` constant with properties: `w`, `h`, `hp`, `speedMul`, `color`, `dark`, `score`, `minStage`
2. Add rendering logic in the `drawEnemy` function
3. Enemies automatically spawn based on `minStage` setting

#### Adding a New Weapon
1. Add weapon class to weapon type constants
2. Implement fire pattern in player firing logic
3. Adjust multiplier bonus in weapon stats section

#### Modifying Difficulty
1. Edit `DIFFICULTIES` constant with spawn rates and multipliers
2. Changes apply immediately with localStorage persistence

#### Adding Visual Effects
Use existing effect patterns:
- **Screen shake**: Modify `shakeAmount`, `shakeDir` variables
- **Flash effects**: Toggle `#flash` element classes
- **Vignette**: Toggle `#vignette` element with `.on` class
- **Animations**: Add CSS keyframes and apply to elements

### Accessibility Features
- **Semantic HTML**: `role="status"` for live announcements
- **Screen reader**: `#srLive` element for game announcements
- **Reduced motion**: Detects `prefers-reduced-motion` system preference
- **Color contrast**: HUD uses high-contrast colors on dark backgrounds
- **Touch targets**: Buttons 78px diameter, minimum recommended size

## Building & Running

### No Build Step Required
Simply open `index.html` in a modern web browser:
```bash
# Local file
file:///path/to/Google_4/index.html

# Or serve locally
python3 -m http.server 8000
# Then visit http://localhost:8000/index.html
```

### Browser Requirements
- **Canvas API**: For rendering
- **Web Audio API**: For sound synthesis (gracefully degrades if unavailable)
- **localStorage**: For persistence (gracefully degrades if unavailable)
- **Touch Events**: For mobile support (optional)

### Testing on Mobile
1. Serve over HTTPS or localhost
2. Open URL on mobile device
3. Touch controls automatically enable
4. Full-screen mode available via device options

## Extension Points

1. **New enemy types**: Add to `ENEMY_TYPES`, implement visuals
2. **New boss designs**: Add to `BOSSES`, customize visual rendering
3. **Additional themes**: Add to `THEMES` with color palettes
4. **Weapon variants**: Expand weapon pattern options
5. **Audio variations**: Create new `beep` or `noiseBurst` calls

### Moderate Enhancements
1. **Boss attack patterns**: Create functions in boss update logic
2. **Particle effects**: Extend explosion system
3. **Combo system refinements**: Enhance multiplier calculation
4. **Stage mechanics**: Add unique rules per stage
5. **Leaderboard**: Integrate with backend API

### Advanced Enhancements
1. **Procedural generation**: Randomize enemy waves
2. **Save/resume**: Persistent game state
3. **Multiplayer**: Network synchronization
4. **Level editor**: Interactive stage builder
5. **Mod system**: Plugin architecture for custom content

## Performance Considerations

### Current Optimizations
- **Canvas rendering**: Direct pixel manipulation for efficiency
- **Entity pooling**: Reuses entity objects where possible
- **Adaptive quality**: Reduces rendering detail on slower devices
- **Audio synthesis**: Real-time generation avoids asset loading
- **No external assets**: Reduces network requests and dependencies

### Potential Improvements
- Implement spatial partitioning for collision detection
- Use WebGL for rendering instead of Canvas 2D
- Add worker threads for physics calculations
- Optimize enemy spawn patterns
- Implement level-of-detail for distant objects
