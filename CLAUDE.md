# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Sky Fighter** is a Raiden-style vertical shoot-'em-up game built as a single-file HTML5 application. The entire game (~1,669 lines) is contained in `index.html` with embedded CSS and JavaScript. It features a player ship, enemy waves, stage bosses, multiple weapons, bombs, particle effects, and a scoring system with difficulty levels.

## Running & Development

### Quick Start
- Simply open `index.html` in a web browser to play the game
- No build step, dependencies, or server required—it's a standalone HTML file
- Works on desktop (mouse control), mobile (touch controls), and has gamepad support

### Development Workflow
The entire codebase is in one file, so making changes is straightforward:
1. Edit `index.html` directly
2. Save and refresh the browser to see changes
3. Test locally by opening the file in a browser or using a simple HTTP server: `python -m http.server 8000` then visit `http://localhost:8000`

### Testing & Validation
- **Manual testing**: Play through different difficulty levels (Easy, Normal, Hard) to verify gameplay feels correct
- **Audio**: Test that sound effects play and muting toggles work
- **Controls**: Verify mouse, touch (mobile), and keyboard controls work
- **Responsive**: Test on different screen sizes and aspect ratios (desktop, tablet, mobile)
- **Performance**: Use browser DevTools to monitor frame rate; the game auto-scales quality if FPS drops below 50

## Code Architecture

The JavaScript is organized sequentially in a single IIFE (Immediately Invoked Function Expression) that runs when the page loads. Key sections:

### 1. **UI Elements & Configuration** (~lines 426–520)
- Canvas and DOM element references
- Storage keys for persistence (best score, mute state, difficulty, reduced motion)
- Difficulty definitions, enemy types, boss data, audio playback themes

### 2. **Audio System** (~lines 545–677)
- Web Audio API wrapper: synthesized sound effects (beeps, noise bursts, effects like reverb/echo)
- No external audio files; all sounds are generated programmatically
- Sound effects for firing, explosions, hits, combo milestones, game over, and victory
- Global mute toggle and stereo panning based on on-screen position

### 3. **Game State** (~lines 864–868)
Core game entities:
```
- player: { x, y, w, h, speed, cooldown, rapid, weapon, level, invuln }
- bullets, enemies, enemyBullets, particles, powerUps, boss
- score, lives, stage, chain (combo counter), multiplier, etc.
```

### 4. **Update Loop** (~lines 1148–1410)
Central game logic that runs every frame:
- **Input handling**: Mouse, keyboard, and touch joystick position
- **Player movement** & weapon fire (cooldown and rapid-fire logic)
- **Bullet physics**: Move, collision detection vs enemies, removal off-screen
- **Enemy AI**: Spawning (timer-based, wave patterns), movement, firing, destruction
- **Powerup handling**: Collection, weapon/bomb/rapidfire buffs
- **Particle updates**: Movement, lifetime, removal
- **Scoring**: Kill chains, combo multipliers, stage progression
- **Boss fights**: Special phase when `stageKills >= KILLS_PER_STAGE`; boss AI in `updateBoss()`

### 5. **Boss System** (~lines 1411–1540)
Separate update function for boss behavior:
- Boss health, movement patterns, firing patterns (spread shots, rotating fire, etc.)
- Boss health bar display
- Victory conditions and stage transitions

### 6. **Rendering** (~lines 1543–1650)
Canvas drawing each frame:
- Player ship, bullets, enemies, powerups, particles
- HUD (hearts, bombs, score, weapon info, combo display)
- Boss health bar, stage banners, combo pop notifications
- Visual effects (flashes for hits/bombs, vignette pulse for low health)

### 7. **Game Loop** (~lines 1652–1669)
- `requestAnimationFrame(loop)` calls `update(dt)` then render
- Delta time calculation for frame-rate-independent physics

## Key Subsystems

### **Enemy System**
- **Spawning**: Timer-based; enemies spawn at top of screen with random horizontal start
- **Types**: Grunt (fast small), Interceptor (medium), Tank (slow, high health)
- **AI**: Simple linear downward movement + directional firing toward player
- **Death**: Triggers particles, sound, score increase (scaled by multiplier and combo chain)

### **Weapon System**
Two primary weapons can be upgraded:
- **Vulcan**: Rapid-fire spray pattern; generated by spawning multiple bullets in a spread
- **Laser**: Focused beam (narrower shot pattern) with lower fire rate
- Switch via `player.weapon` toggle; level upgrades improve fire rate and spread

### **Multiplier & Combo Chain**
- **Chain Counter**: Increments when enemies killed; resets if player takes damage or time elapses
- **Multiplier**: Scales from 1x up to 8x; visual feedback in HUD and combo pop animation
- Encourages aggressive, skillful play without taking hits

### **Bombs & Powerups**
- **Bombs**: Limited (2–4 per life, difficulty-dependent); destroy all bullets/enemies on-screen when triggered
- **Powerups**: Dropped by specific enemies; grant weapon level, rapid-fire cooldown, extra bombs
- **Smart Bomb Cascade**: Bombs trigger chain reactions (enemies destroyed by blast trigger chain, score multiplier applies)

### **Difficulty Levels**
Defined in `DIFFICULTIES` object:
- **Easy**: More lives, slower enemies, lower spawn rate
- **Normal** (default): Balanced
- **Hard**: Fewer lives, faster enemies, tighter enemy patterns
- Applied at `resetGame()` time; persisted in localStorage

### **Responsive & Accessibility**
- **Touch Controls**: Virtual joystick on mobile + fire/bomb buttons
- **Motion Preferences**: Respects `prefers-reduced-motion`; toggles screen shake, flashes, pulsing animations
- **Screen Reader Support**: ARIA live region (`#srLive`) announces game events (stage, victory, game over)
- **Responsive Canvas**: Maintains aspect ratio, scales for phone/tablet/desktop

## Performance Considerations

### **Quality Scaling**
The game monitors frame rate and auto-scales rendering quality:
- **Quality 0** (full): All particles, effects, shadows
- **Quality 1** (medium): Reduced particle count
- **Quality 2** (low): Minimal particles, simplified rendering
Scaling kicks in if FPS consistently drops below 50.

### **Optimization Tips**
- Particle count is the largest draw on performance; limit spawned particles per explosion
- Enemy bullet count grows with wave intensity; consider pooling or culling off-screen bullets
- Canvas context calls are batched per frame; avoid excessive `save()`/`restore()` calls
- Use `quality` variable to skip expensive operations in low-quality modes

## Common Tasks for Claude

### **Adding a New Enemy Type**
1. Add entry to `ENEMY_TYPES` object with properties: `hp`, `speed`, `fireRate`, `fireSpread`, `reward`
2. Add sprite/shape drawing in `render()` function under enemy loop
3. Add spawn logic in `update()` if type needs special handling
4. Optionally add explosion sound variant in `EXPLODE_SFX` and `sfx` system

### **Adding a New Weapon or Powerup**
1. Extend weapon logic in player update (cooldown, spread, bullet lifetime)
2. Add drawing code in `render()` for bullet sprites/trails
3. Create or reuse a powerup type in the spawn system
4. Scale difficulty (e.g., weapon fire rate adjusted per difficulty)

### **Tuning Difficulty or Balance**
- Edit `DIFFICULTIES` object for lives/enemy spawn rates/boss health
- Adjust `KILLS_PER_STAGE` to control stage length
- Modify `ENEMY_TYPES` properties (speed, fire rate) to speed up or slow down gameplay
- Test across all three difficulty levels after changes

### **Adding Sound Effects**
- Add a new synth definition to the `sfx` object (e.g., `sfx.mySound = { ... }`)
- Call `beep()` or `noiseBurst()` with frequency, duration, and volume
- Use `panFor()` to position audio left/right based on on-screen position

### **Visual Tweaks**
- Particle colors and speeds are defined in `render()` explosion code
- Boss health bar appearance is in CSS (search `#bossBarFill`)
- HUD layout and colors are in the CSS `:root` and `#hud` sections
- Screen flash/vignette animations (hit, bomb, low health) are CSS keyframes

## Browser Compatibility

- Requires **HTML5 Canvas**, **Web Audio API**, and **ES6 (const/let, arrow functions)**
- Tested on modern browsers (Chrome, Firefox, Safari, Edge)
- Mobile: iOS Safari, Android Chrome
- Older browsers (IE, very old Safari) will not work

## localStorage Keys

The game persists:
- `skyfighter.bestScore` — High score
- `skyfighter.muted` — Audio mute state
- `skyfighter.difficulty` — Last selected difficulty
- `skyfighter.reducedMotion` — Reduced motion preference

## Note on Code Style

The codebase is written as a monolithic IIFE with procedural update/render loops rather than classes or modules. This keeps the game lightweight and fast to load. When adding features, prefer:
- Inline object literals for entity state (e.g., `player = { x, y, ... }`)
- Functional update patterns (modify state in place, call render after update)
- Direct canvas context calls for rendering (no higher abstraction layer)

This style is intentional for performance and simplicity; resist urge to refactor into OOP architecture unless performance dictates otherwise.
